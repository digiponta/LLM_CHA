# LLM_CHA v0.4.28 — Safe Sleep Experiment Runner (Stage 1)

**Safety boundary:** The tool intentionally DOES NOT execute `/sleep`, invoke training, load arbitrary checkpoints, switch the production model, or promote a trained candidate. This is a snapshot/comparison harness, not a complete automated training runner. Promotion/rollback and isolated actual training remain future stages.

## Checkpoint snapshot

First identify the **actual active checkpoint path** from the chat startup banner. Do not assume it is `model/model.pt`. Set this path explicitly:

```powershell
$active = "REPLACE_WITH_ACTUAL_ACTIVE_CHECKPOINT_PATH.pt"
python safe_sleep_runner_v0428.py snapshot --source $active --destination results/sleep_v0428/before.pt
```

The copy is verified with SHA256; pre-existing output files cannot be overwritten. Copy the learning state and training queue separately as necessary for your isolated test.

## Paired audit (after separately obtaining real captures)

Collect the exact same fixed question set with identical decoding configuration on a known pre-sleep checkpoint and a separately trained candidate checkpoint. Record IDs, configuration and run environment separately. Do not run production `/sleep` solely for this test: the existing implementation reloads its output directly.

Ensure that `results/sleep_before_v0427.jsonl` and `results/sleep_after_v0427.jsonl` are both real capture JSONL datasets, one row per question, each following the v0.4.24 schema. Make a fresh, unused report filename.

```powershell
python safe_sleep_runner_v0428.py compare `
  --before-checkpoint results/sleep_v0428/before.pt `
  --after-checkpoint results/sleep_v0428/candidate.pt `
  --before-capture results/sleep_before_v0427.jsonl `
  --after-capture results/sleep_after_v0427.jsonl `
  --report results/sleep_v0428/comparison.json
```

This validates existence of all four input files, computes SHA256 identifiers, checks matched questions, and reports changed answers and scores. It does not prove two captures were generated by the named checkpoints, nor that changed outputs improved quality. No candidate is adopted automatically. Human-labeled quality and a proper independent holdout must be added before a later promotion gate.
